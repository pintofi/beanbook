### Fixed
- The entry form no longer refuses entries that Beancount accepts: the balance check follows Beancount's per-currency tolerance rule. Typed lots accept thousands separators. (#52)
- A save interrupted by the screen closing is finished or put back, never left undecided, and a raw edit you typed survives a crash while the engine is down. (#59)
- Undo after restoring a backup can no longer put the old project's files over the restored ones, and stays in order if the clock is reset. (#59)
- A damaged saved copy is refused instead of being restored over an intact ledger. (#59)
- The project picker no longer fails after restoring a backup. (#59)
- Backups: the check is bounded in memory, files named `key` are included, and diagnostics redact tokens and passphrases. (#59)
- Editing a ledger with Windows (CRLF) line endings keeps them. (#62)
- A cached answer is no longer reused after a plugin or the app changes, and a failed engine start no longer stalls later reads. (#62)
- Remote server addresses with capital letters or a path prefix such as `/fava` work, and an odd reply ends in an error message instead of a crash. (#64)
- A link in a report opens only after you confirm. Deleting or editing an entry checks that it is still the one you were looking at, and the report view survives Android closing it. (#71)
- The entry form refuses an amount it cannot read, such as `4,50`. Deleting a selection that includes a plugin-generated entry no longer removes the next one, and removing a package or script asks first. (#74)
- The document scanner frees its image memory as it goes. (#78)
- Unlinking a document no longer removes the link of a different document with the same file name. (#92, fixes #48)
- Receipt photos and attached copies are removed from the app's cache once the document is filed. (#93, fixes #69)
- Restoring a deleted project whose name has been reused brings it back under the next free name, instead of refusing. (#103, fixes #101)
- The Trash can be reached after deleting the only project, and restoring from it opens the project. (#103, fixes #102)

### New
- Deleted projects are listed in a Trash on the Projects screen, with their size. Put one back, or delete it for good, one at a time or all together. (#94, fixes #57)

### Changed
- Each processor type has its own APK, so a phone downloads only its own libraries. The universal APK stays for any device. (#90, #97)
- The bundled Python runtime is 3.13.16 (Chaquopy 17.1.0). (#98)
- Wording and punctuation tightened in the app's messages, the docs and the site. (#89)

### Maintenance
- Gradle dependencies are checked against recorded checksums. (#95, fixes #82)
- Pinned GitHub Actions updated, and the Gradle cache uses the open-source provider. (#96)
- The large-ledger test skips instead of failing when its corpus is absent. (#91, fixes #79)
- A review of every file in the repository ([#16](https://github.com/pintofi/beanbook/issues/16)): the build and release jobs are limited to what they need and a tag must match the version (#83), and the catalogue, docs, threat model, privacy page and site were corrected to match the code (#84, #86, #87, #88).
- The F-Droid recipe builds each processor type separately. (#100)
