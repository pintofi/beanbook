## Fixed in this pull request

- **B-1 (S2): the release workflow held write access to the repository for every job.** The token is now read-only by default and only the job that publishes the draft release is given `contents: write`. The called `verify` workflow runs with the read-only token.
- **B-2 (S2): a manual run of the release workflow on a branch would have signed and drafted a release named after the branch.** The release job now runs only when the ref is a tag.
- **B-3 (S2): nothing checked that the tag matched the version inside the APK.** A tag `v1.2.3` with `versionName = "1.0.0"` would have published files named 1.2.3 holding 1.0.0. The release now stops if they differ.
- **B-4 (S1): the Python engine tests were not run in CI.** The 153 tests of the writer, the engine gate, the ledger reader and the plugin runner ran only on a developer's machine. A new `python` job runs them on Python 3.13 with Beancount 3.2.3, the version the app ships. Its first run found that one test (`CompanionLibraryTest`) looked for `libz.so.1` only in `/usr/lib*` and `/lib*`, which misses the multiarch directories on Ubuntu; it searches one level deeper now.
- **B-5 (S3):** about 40 private ids and references to documents that are not in the repository removed from comments; `verify.yml` now declares a read-only token of its own.
- **B-6 (S3):** a ProGuard keep rule for `net.i2p.crypto.eddsa`, a library the app no longer contains, removed.
- **B-7 (S2): the Gradle distribution was not checksummed.** `gradle-wrapper.properties` now carries `distributionSha256Sum` for gradle-9.8.1-bin.zip, taken from services.gradle.org. It is checked when the distribution is downloaded; this machine already had it cached, so that path was not run here.

## Filed as issues

- **B-8 (S2)** Gradle dependency verification is not enabled, so the checksums of the libraries Gradle downloads are not checked: [#82](https://github.com/pintofi/beanbook/issues/82).

## Accepted, with the reason

- **Material3 is pinned to a beta above the Compose BOM.** The Expressive components are not in the stable version. The reasoning is in `libs.versions.toml` and `dependabot.yml`; return to the BOM when a stable BOM carries it.
- **Release signing passwords are in the environment of the Gradle step.** Anything Gradle runs can read them. That is true of any signed CI build; the protection is that only a tag can reach this job and only people who can change the workflow can change what runs.
