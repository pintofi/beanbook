Help

Start with a project, not an account.

Create a ledger or import a complete project tree. The app reads the same Beancount syntax used on desktop.

Getting started

  1. Open Projects.Create a new ledger, select a folder tree, or select an archive.
  2. Keep the whole tree together.Import the project rather than only one file so includes and document links remain valid.
  3. Fix ordinary parse errors.Import completes even if Beancount reports errors, so you can correct them in the raw editor with file, line, and column information.
  4. Export a copy.Keep an ordinary folder for desktop use, create a backup archive, or configure Tier 2 mirroring.

Importing an existing ledger

Import the whole folder tree or an archive, not only the root .beancount file. That keeps included files and linked documents together.

Imported projects keep their own layout. The app does not require the folder names used for a new project.

Before writing anything, import rejects path traversal, absolute paths, archive symlinks, zip bombs, case collisions, and duplicate names. It imports into a new project rather than overwriting an existing one.

Where your files live

The app-private workspace is canonical. This is required because Python and Fava need real POSIX paths, while Android's folder picker provides content URIs.

Canonical workspace

Projects live in app-private storage. Modern file managers cannot browse that location.

In-app raw editor

Every included file remains directly editable inside the app. This is permanently free.

Portable copies

Import, export, and mirror connect the private workspace to a folder chosen through Android's Storage Access Framework.

Clean project tree

Caches, logs, credentials, generated state, and entitlement keys live outside the portable project tree.

Troubleshooting

A ledger will not load

Open the reported file, line, and column in the raw editor. A file Beancount cannot parse is reported rather than silently interpreted.

A save was refused

The file may have changed since the editor opened. Stale-write detection refuses last-write-wins and offers a conflict view.

A plugin stops startup

Use safe mode to disable third-party code and open the ledger read-only. Recovery mode remains available after a startup failure.

A remote server will not connect

Check the scheme and certificate. Certificate errors for https:// are fatal. The app never retries over http://.

An Expert package will not install

Some dependencies have no compatible Android wheel. The package resolver shows what is available before downloading.

What it does not do

These are product limits, not hidden roadmap promises.

No Git integration

The app can edit a working tree but leaves version control to you.

No remote offline cache

Remote mode requires the server and provides reports plus quick-add, not existing-entry editing or two-way sync.

No 32-bit support

Only arm64-v8a and x86_64 builds are provided.

No OCR in v1

Camera capture and PDF assembly ship first. OCR is deferred.

No plugin marketplace

You supply plugin files. The app does not provide a vetted catalog.

English UI only

The UI is prepared for localization, but translations do not exist yet.

Large ledgers cost time once.

The app was built and measured around roughly 25,000 transactions in about 10 MB. Larger ledgers are not refused: just over 100,000 entries loads correctly. What it costs is the first load after a change, which runs to tens of seconds at that size. Opening the app again is quick, because the figures the native screens need are cached and re-checked against the contents of your files. Fava reports and BQL queries still do a full load every time, so those stay slow on a large ledger.
